# Stage 12 (slice 16) — the navbar redesigned as a permanently-floating capsule

The ask: "the navbar is very basic… make it the best looking navbar in a website in the world," plus a reference screenshot of a premium homepage (a photographic hero, "A World of Gifts. A World of Emotions.", a floating dark navbar) to draw on without copying literally.

## The decision: always a capsule, never a bar, never transparent-and-chameleon

The reference reads as a rounded, inset, dark-green pill sitting a little above the page — not a fully transparent bar that has to match whatever's underneath it. A transparent header would need to know, on every single page, whether what's behind it at that instant is light or dark (a photographic hero vs. the plain cream page everywhere else) and flip every piece of text/icon colour accordingly — fragile, and wrong the moment a page's top strip is the "wrong" brightness. Committing instead to **one fixed look, everywhere**: the header is the same deep-forest-green capsule (`--gp-primary`, matching the announcement strip above it and the footer below), the same cream/copper ink, on the homepage's hero and on a plain category listing alike. It never has to reason about what's behind it, so it can never clash with it either.

This replaces the earlier "full bar at rest → floating pill on scroll" behaviour (Stage 12's quick-fixes slice) with "roomy pill at rest → tighter pill on scroll" — the same condense mechanism (`HeaderShell.tsx`'s scroll listener, `.gp-header[data-condensed]`), just without the shape change, since it was always the pill now. The outer `<header>` is fully `pointer-events: none` at all times (not only once condensed) — the pill itself (`.gp-header-inner`) re-enables clicks, and the empty margin around it lets the page underneath receive scroll/clicks exactly as before.

Nothing here is a new colour: the capsule, its border and its text are `--gp-primary`/`--gp-copper`/`--gp-on-primary`, already defined tokens — so a festival theme that redefines them reskins the nav automatically, same as everywhere else (`lib/theme/theme-safety.test.ts` still passes untouched).

## What actually got built

- **`app/globals.css`**: the header CSS rewritten around the permanent capsule — a soft two-layer gradient background, a hairline copper edge, an inset highlight for a touch of glass, a deeper shadow that tightens on scroll. New animation keyframes for the mega-menu's entrance and a shared `.gp-menu-pop` used by both new dropdown panels (driven by Radix's own `data-state`, since the animate plugin isn't installed — Radix's `Presence` keeps a closing panel mounted through the animation on its own, as long as something is a real `animation`, not a `transition`).
- **`components/layout/NavLinks.tsx`**: real mega-menus. Hovering (or focusing, for keyboard use) **Occasions** or **Boutiques** opens a light card below the pill — a curated preview (`getFeaturedCategories()`/`getFeaturedVendors()`, the same admin-curated "featured" flag the homepage already uses), not the full list, each with a "see every…" link to the real page. A short close delay (180ms) forgives the mouse crossing the gap between the trigger and the panel. Every other item gets its own pill highlight (hover fill, a small copper underline dash when it's the current page) instead of the old plain underline-on-hover.
- **`components/layout/AccountMenu.tsx`**: rebuilt bespoke on Radix `DropdownMenu` directly (matching how the notification bell already does it, not the site's generic `ui/Dropdown` used by admin/vendor tables) — an initial roundel that echoes as the header trigger and again inside the panel, an icon in a soft roundel per row, a divider before Sign Out, and Sign Out set visibly apart (the theme-safety test's own stated exception: "the red family for error/danger states").
- **`components/layout/Navbar.tsx`, `NotificationBell.tsx`, `MobileMenu.tsx`**: every icon/link inside the pill switched from the site's usual dark-ink-on-cream classes to cream-on-forest-green ones; the "My Diary" button — previously `bg-brand-primary`, which would have been invisible against its own now-primary-coloured header — is copper, the one accent that reads cleanly against forest green. The phone menu's link list gained an icon roundel and a chevron per row, and its own "My Diary" button matches the copper treatment.
- **`lib/db/categories.ts` / `lib/db/vendors.ts`**: `getFeaturedCategories()`/`getFeaturedVendors()` wrapped in React's `cache()` — the exact pattern already used for `getServerUser()`/`getActiveTheme()` — since the navbar now asks for both on literally every request, and the homepage already asks `getFeaturedVendors()` for its own showcase section; without this they'd run twice in the same request.

## A repeat of the documented `transform`/`translate` gotcha — caught before shipping

The mega-menu's centring (`left: 50%` + Tailwind's `-translate-x-1/2`) landed nowhere near its trigger — off by exactly half the panel's own width. Cause: Tailwind v4 compiles `-translate-x-1/2` to the *separate* CSS `translate` property, not into `transform`; the panel's own CSS rule *also* sets `transform: translate(-50%, 0)` for its open/closed animation. Per spec, `translate` applies first and `transform` wraps around it — so the shift happened twice. This is the exact rule CLAUDE.md already records from the robin cursor bug (never mix Tailwind's individual `translate`/`scale`/`rotate` utilities with a `transform` rule on the same element for the same axis) — caught this time by measuring the rendered position rather than trusting the screenshot, and fixed by dropping the Tailwind utility and leaving the CSS rule to own the whole transform.

## Verified

Hover-opened both mega-menus at 1440×900 (correctly centred, populated, closes on mouse-out); scroll-condense with a menu open (repositions correctly, stays legible); a real click through the pill navigated correctly (`elementFromPoint` resolves to the link itself, confirming the `pointer-events: none` outer header doesn't shadow it); the same header over a hero page (home) and a plain page (`/categories`) look identical and legible; mobile (390px) header + slide-out menu; `tsc`, `eslint`, `vitest` (291, including theme-safety) and `next build` all clean. The diary's own `--dy-chrome` fit numbers were nudged for the header's new height (+0.4375rem) and re-confirmed still fitting without scroll at 1440×900 and 1440×780.
